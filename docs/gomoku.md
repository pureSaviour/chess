# 五子棋玩法与开发边界

更新：2026-09-10。本文只描述已实现行为；AI 仍未实现。

## 规则

- 棋盘默认 15×15，创建房间可选 9..25 路；黑先，双方交替在空交叉点落子。
- 无禁手模式中，任一方连成五子或更多获胜。
- 连珠禁手模式中，只限制黑方：长连、双四、双三落子被拒绝且局面不变；黑方只有恰好五子获胜，白方五子或更多获胜。本版不包含交换开局规则。
- 禁手以 RIF 定义为设计基线。测试覆盖长连、双四、双三；赛事级复杂“假三”局面仍需棋库对拍验收。

## 分层与抽象

`GridPoint` 是零基交叉点，`SquareGrid` 只校验边长、越界与有界射线。它不存储棋子、不判规则、不知道 Godot 像素，可作为后续围棋领域对象的几何依赖。当前是方形 3..25 路，不表达军旗图拓扑或三国棋盘。

`GomokuGame` 拥有占位、轮次、历史和终局；`TryPlace` 是唯一写入口，越界、重叠、错误行棋方和禁手均不修改局面。`GomokuSnapshot` 是展示快照，UI 不得反向修改权威聚合。

`IGomokuMatchController` 是 UI 的实际注入边界。本地实现使用同一聚合；联机实现复用 `ITwoPlayerPacketTransport`，但使用独立 v1、16000 字节上限的房主权威协议。房主 hello 发布尺寸、禁手和席位；客户落子携带预期手数；房主发布主线，客户端逐手重放后才接受。未知版本、越界、错误角色、陈旧手数和畸形 JSON 失败关闭。这是可信 P2P 房主模型，尚无断线续局或中立裁判。

事件在 transport 驱动线程同步发布；Godot 适配器在主线程泵入。Screen 拥有 controller，退出时先解绑再幂等释放；controller 再释放 transport。`GomokuBoardView` 只绘制、命中和播放落子动画。

## 棋谱、UI 与限制

`GomokuSgfCodec` 读写 SGF FF[4]/GM[4]，使用 `SZ/RU/AB/AW/PL/B/W` 主线。解析最多 1,000,000 字符，未知属性/变例不进入主线，返回前必须通过领域重放。`GomokuRecordStore` 拥有 `user://records/gomoku`，recent 保留十局，saved 不自动清理。当前小文件 I/O 同步发生在主线程。

画廊提供与经典象棋同构的 9 个叶子：本地/LAN/Steam，最近/保存，SGF/局面导入，人机对决/设置。前七个已接通；两个 AI 叶子仅告知尚未实现。

核心自运行测试覆盖几何、规则、禁手、SGF 和 fake transport。真实双机 LAN、Steam 双账号、Android 触控、多分辨率与复杂禁手棋库对拍尚未验收。
